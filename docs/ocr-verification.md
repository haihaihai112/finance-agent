# 文档、理赔与信用表单验证

## 当前实现

- DocumentStore(engine, storage_dir) 使用独立 SQLAlchemy 表保存上传元数据和提取缓存，磁盘文件名使用服务器生成的 UUID。每次查询、读取和缓存访问均按 user_id 与 document_id 联合过滤。
- 上传仅接受内容与扩展名一致的 PDF、PNG、JPEG；默认 10 MiB，最多 30 页 PDF、2500 万像素图片；拒绝损坏、加密及空 PDF。
- 原生文本 PDF 用 PyMuPDF 直接解析；没有原生文本的页渲染后调用 RapidOCR ONNX。图片直接调用同一 ONNX 引擎。扫描件缺依赖或推理失败时明确返回不可用。
- 每个提取字段保留文档 ID、来源、页码、原文片段、坐标和置信度；PDF 文本坐标为 PDF 点，OCR 坐标为渲染图片像素。文本解析置信度 1 表示直接文本读取，并不代表业务数据正确。
- 标签规则支持金额、万单位、常见币种、保单、条款版本、事故日期和贷款表单字段；未注明币种保留 UNK，必须补充确认。未自动执行外汇换算。
- 信贷表单合并多文档和用户提示。数值等价不会误报冲突；数值不一致保留证据并追问；更改已确认字段会取消旧确认。确认后追加单据如出现矛盾，即使进入授权阶段也会撤销相关确认、保留原确认值与新旧材料证据并追问；对已核对旧材料的明确纠正值仍有效。理赔使用同一原则。完整字段、全部提供的数值确认和有效授权通过后才生成 CreditModelInput。首版大陆贷款演示仅支持人民币 CNY，其他币种明确拒绝，不自动换算。
- CreditMCPService 的公共 evaluate_mock 工具还检查 confirmed_fields；可信运行时负责验证授权的所属用户、运行、有效期和当前表单。内部 evaluate_form 不单独注册为 MCP 工具。
- 风控仅使用 demo-v1 的确定性模拟规则，输出 Decimal 字符串及公式。月负债率包含本金平均月还款，不计算利息；0.5 阈值仅为演示参数。无真实征信查询、银行模型或授信决定。
- 理赔历史通过 ClaimsStore 按用户和版本查询；真实／脱敏记录须包含来源 URI，缺条款返回不可用。seed_demo(user_id) 只为显式指定用户创建模拟保单，不自动共享给其他用户。条款匹配为结构化事故类型匹配和有效期初筛，不计算赔付。

## 本次验证证据

命令：`.venv/Scripts/python.exe -m pytest tests/test_documents_credit.py -q`。

31 项测试覆盖文档越权、格式拒绝、原生文本 PDF、提取缓存、Decimal／单位／币种、冲突、变更后重新确认、公共工具确认门禁、授权、演示数据归属、缺条款、完整信贷和理赔流程，以及四类理赔初筛和两类模拟信贷结果的中文表达。新增回归验证确认后上传矛盾材料会阻断工具调用，而已核对旧 OCR 的用户纠正值保持有效、再次纠正后不会重复产生同一冲突。

金额提取要求完整数字串与单位边界。`1,23` 和 `1.2.3` 等非法格式整体拒绝，不截取为 `1` 或 `1.2`；合法的 `1,234.56` 与 `1.25万元` 保留精确数值。文档提取成功后才整批合并字段，避免部分读取失败时提前把新证据当作已处理。

真实 OCR 测试使用人工生成的中文 PNG「月收入：8000元」，并将该图放入无文字层 PDF，两个输入均实际调用 RapidOCR 3.10.0 ONNX 推理，验证提取金额 8000、OCR 来源、页码、坐标与置信度。另有两行两列的「月收入／8000元」「月还款／1000元」图片，验证同一视觉行中的标签和值可以合并提取，坐标保留该行的外接框、置信度取该行识别结果最小值。测试图使用 PyMuPDF 内置 china-s 中文字体渲染，无需操作系统字体。全角数字和小数标点可作等价归一化，仍保留原始识别片段，不推断缺字或自动纠正其他数字。

## 范围与限制

没有实测数据集或准确率结论。手写、倾斜、模糊、复杂表格和未知标签可能无法提取，仍须人工核对。当前含原生文字的 PDF 页直接解析文字层，不识别该页内嵌图片正文；没有文字层的扫描页可识别。OCR 模型文件首次运行可能需要获取，部署环境须准备可用模型和依赖。

这组测试不访问真实征信、执行贷款审批或发起保险赔付。MySQL 接入复用 SQLAlchemy 引擎；本工作包自动测试使用 SQLite，MySQL 集成由项目整体验证负责。
