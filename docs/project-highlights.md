# 项目简介与面试亮点

## 可用简介

构建金融多智能体个人项目，采用FastAPI、LangGraph、SQLAlchemy和MCP SDK，覆盖投资咨询、理赔申请、贷款申请、政策/税务及其他五类意图。实现用户画像追问、日频基金净值采集与版本审计、共享OCR提取、历史保单查询，以及由多单据和用户提示形成的信贷表单；字段确认并授权后提交结构化模型输入，结果保留计算、证据与模拟标记。

使用真实公开净值和官方个税资料，保单演示与风控采用明确标注的模拟规则。本地SQLite与实际OCR/MCP路径已验证；MySQL真实服务与DeepSeek付费调用待相应环境验证。

## 面试讲述顺序

业务问题：单据中的数字和自然语言不能直接作为可靠的风控模型输入。

设计：OCR保留页码、原文与置信度；结合提示形成表单，缺失和冲突追问，用户明确确认及授权后转换为严格表格行，通过MCP调用规则，再展示结果和限制。

工程难点：补答时保留最初任务目标；确认表单先持久化再调用外部工具；授权撤销必须在工具边界实时检查；行情失败不推进水位，来源修订需审计。

取舍：个人项目用规则风控和透明配置模板以便复算；政策使用已核验版本和人工变更审核；本地身份机制方便演示。介绍时明确真实数据、模拟业务与未验证外部服务。

可后续扩展：真实风控模型契约、金融票据专用OCR基准、复杂表格、MCP连接池、完整数据库版本迁移框架、SSO、向量检索。当前仅实现请求表的可重复增量迁移，不等于已经具备通用迁移平台。不要把后续扩展写成已完成。

不填写未经测量的准确率、吞吐量、成本降低、收益或业务转化指标。已有测试数量是工程验证数量，不代表真实金融效果。

交付诊断仅能说明本地核心包、配置模式、OCR模型文件和端口状态。模型文件存在不等于推理成功；DeepSeek密钥存在不等于调用成功；MySQL模式被识别不等于连接成功。新增历史与报告功能的执行证据以 [验收记录](verification.md) 和 [个人项目验收清单](personal-project-acceptance.md) 为准，不把待执行步骤描述为已验证。🧾
